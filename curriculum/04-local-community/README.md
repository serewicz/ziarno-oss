# Module 4: Building a local open-source community

**Level:** Practitioner  
**Time:** about 5 hours  
**Needs:** a laptop or a phone with a browser; some exercises need an internet connection once.

## Learning objectives
By the end you will be able to:
- Plan and run a first meetup
- Write and enforce a code of conduct
- Set up simple mentoring
- Keep volunteers from burning out

## Lesson outline
1. Why local communities matter: trust, language, local problems
2. Starting small: five people and a regular date beat one big launch
3. Meetup formats: talks, install days, hack nights, study groups
4. Codes of conduct: why, how to write one, how to respond to a report
5. Mentoring pairs and good first tasks
6. Sustaining volunteers: rotate roles, thank people in public, keep a written handbook
7. Inclusive communities from day one

## Hands-on exercise: Plan your first meetup
1. Open https://opensource.guide/building-community/ and read the section **Setting your project up for success**.
2. Pick a date four weeks away, a free room (office, library, university lab, café), and one topic from this curriculum.
3. Write a one-paragraph invitation: what, when, where, who it is for, what to bring. Keep it short enough for a phone message.
4. Open https://www.contributor-covenant.org/version/2/1/code_of_conduct/ . Copy the text into a document. Replace the contact line with a real email or phone number of two people who will handle reports.
5. Make a sign-in sheet with name, contact, and "what would you like to learn next".
6. Write a run sheet: welcome (10 min), introductions (15 min), main topic (45 min), open questions (20 min), next date (5 min).
7. After the meetup, send a thank-you message within two days with the next date.

## Quiz
1. Why have two contacts for code of conduct reports?
2. Name one way to keep volunteers from burning out.
3. What is a good size for a first meetup?

<details><summary>Answers</summary>

1. So a person can report even if one contact is involved.
2. Rotate roles; thank them publicly; keep tasks small; write things down.
3. Small. Five to fifteen people is fine.

</details>
