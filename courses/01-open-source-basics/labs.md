# Labs: Getting started with open source

All labs need only a web browser.

## Lab 0 (before the day): Create a GitHub account
1. Go to https://github.com/signup
2. Type your email. Click **Continue**.
3. Make a password. Click **Continue**.
4. Choose a username. Click **Continue**.
5. Solve the puzzle if one appears.
6. Open your email, find the code from GitHub, and type it in.

## Lab 1: Read three real licenses (30 min)
1. Go to https://choosealicense.com/licenses/
2. Click **MIT License**. Read the green, blue, and red boxes ("Permissions," "Conditions," "Limitations").
3. Write down, in one sentence, what MIT asks of you.
4. Click your browser's **Back** button. Click **Apache License 2.0**. Repeat step 3.
5. Go back. Click **GNU GPLv3**. Repeat step 3.
6. Answer with your partner: A company wants to use code in a product it sells without sharing its own code. Which of the three licenses is easiest for them? Which makes it hardest? Why?

## Lab 2: Size up a project (45 min)
Pick one project: https://github.com/ollama/ollama, https://github.com/nextcloud/server, or one your instructor names.
1. Open the project page.
2. Scroll down to read the README. Write one sentence on what it does.
3. Near the top right, find the **License** link. What license is it?
4. Click the **Issues** tab. How many issues are open?
5. Click **Labels**. Look for a label such as `good first issue`. Click it.
6. Click the **Pull requests** tab. Open one closed pull request. Did someone review it? Was the tone friendly?
7. Look for CONTRIBUTING.md and CODE_OF_CONDUCT.md in the file list.
8. Score the project 1 to 5 for "Would a beginner feel welcome?" and explain to your partner.

## Lab 3: Your first issue and pull request (70 min)
Your instructor will make a practice repository for the class, called the **class repo**.
### Part A: Open an issue
1. Open the class repo link.
2. Click **Issues**, then the green **New issue** button.
3. Title: `Add <your name> to the attendee list`.
4. Write one line saying who you are. Click **Submit new issue**.
### Part B: Make a pull request
1. Go back to the class repo main page (click the repo name at top).
2. Click the file `ATTENDEES.md`.
3. Click the pencil icon (**Edit this file**). GitHub may say you need to fork. Click **Fork this repository**.
4. Add a new line at the bottom: your name and city.
5. Click the green **Commit changes...** button. In the message, type `Add <your name>`. Click **Propose changes**.
6. Click **Create pull request**. In the text box, type `Closes #` and your issue number. Click **Create pull request** again.
7. Wait for review. Your partner will leave a comment. Reply to it.
### Part C: Review someone else
1. On the class repo, click **Pull requests**.
2. Open your partner's pull request. Click the **Files changed** tab.
3. Click **Review changes**, write one kind and useful comment, choose **Comment**, and click **Submit review**.
