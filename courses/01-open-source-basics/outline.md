# Outline: Getting started with open source

## By the end of the day, each person can
1. Explain what makes software "open source," in their own words.
2. Tell the difference between permissive and copyleft licenses, and pick one for a project.
3. Find a project's community, rules, and a good first task.
4. Make a first contribution (an issue and a pull request).
5. Explain how projects are governed, and why it matters to a government or company that depends on them.
6. Teach module 1 to co-workers using this material.

## Modules
1. **What open source is.** The Open Source Definition (https://opensource.org/osd). Free to use, study, change, and share. Open source vs. "free of charge."
2. **Licenses.** Permissive (MIT, Apache-2.0, BSD) vs. copyleft (GPL, AGPL). What each asks of you. How to read a LICENSE file. Choosealicense.com.
3. **Communities.** README, CONTRIBUTING, CODE_OF_CONDUCT, issue trackers, chat and mailing lists. How to ask a good question.
4. **Contributing.** Issues, forks, branches, pull requests, review. Non-code contributions: docs, translation, testing.
5. **Governance.** Single-company projects, foundations, meritocracy, elected steering groups. Risk: what happens if a project changes its license or its owner leaves.
6. **Open source at home.** Using open source in your workplace and government. Who maintains it locally.
7. **Teach-back.** Each person teaches one module for 5 minutes.

## Before the day (participants)
- A laptop with a web browser.
- A free GitHub account (lab 1 shows how).
