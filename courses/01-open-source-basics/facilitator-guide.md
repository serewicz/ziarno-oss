# Facilitator guide: Getting started with open source

## The week before
- Make the class repo: a new public GitHub repo with a file called `ATTENDEES.md` containing the line `# Attendees`.
- Send Lab 0 to everyone. Ask them to bring their GitHub username.
- Test the room's Wi-Fi with 20 people if you can. Have a phone hotspot as backup.

## Tips per module
- **Module 1:** Ask "What open-source software did you use this week?" Most people find they use a lot (Android, Linux servers, web browsers).
- **Module 2:** Do not give legal advice. Say: "This is how to read a license. For a real decision, ask a lawyer."
- **Lab 3:** The fork step confuses people. Demo it once on the projector, slowly, before they start. Merge pull requests live on screen so people see the result.
- **Module 5:** Use a real example from your own work if you have one, such as a tool your team uses that changed its license.

## Common problems
| Problem | Fix |
|---------|-----|
| GitHub email code does not arrive | Check spam. Pair them with a partner while they wait. |
| Two people edit the same line | That is a merge conflict. Good teaching moment. Resolve it on screen. |
| Slow internet | Do Labs 1 and 2 as pairs on one laptop. |

## Teaching it next
When you run this for your co-workers, you can split it into three 2-hour sessions: modules 1–2, modules 3–4, modules 5–6.
